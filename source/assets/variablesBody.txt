Precedence: global vars < host vars < apply chain < file vars. 

Strings are templated with {{ name }} / {{ table.key }}; 

The builtin {{ inventory_hostname }} holds the current host name. 

A var of the form { env = "NAME" }  is replaced by the value of that environment variable.

A var of the form { env = "NAME", default = "ABCDEF" } is replaced by the default when NAME is unset.

A var of the form { env = "NAME", from = ".env" }) 
reads from the dotenv file named by 'from' (relative to the declaring file) instead of the process environment.

Inventory vars read the controller's environment.
Tasks-file vars reads the environment of the process that loads them (the host, in bundled mode). 

An unset variable without a default is an error. 

A var of the form { run = "command" } is replaced by the command's captured output — stdout by default, or stderr with stream = "stderr". 

The command runs through /bin/sh -c in the declaring file's directory, in the environment of the process loading the file — at the same place and time an { env } entry resolves (so a bundled tasks file runs it on the host; the controller's validation load runs it once there too). 

One trailing newline is stripped; a failing command, or non-UTF-8 output, is a load-time error naming the variable, the command and the status. 

'run' cannot combine with 'env', 'default', 'from' or 'age'.

Inventory vars may also hold { age = "file.age" }: 
  replaced by that file's age-decrypted content (one trailing newline stripped), on the controller, 
  with the identity from --identity, the config identity entry, AGE_IDENTITY or ~/.ssh/id_ed25519. 

Binary secrets do not fit variables ! 
  Deploy them with a file src marked age = true instead: 
  the source is age-encrypted, decrypted on the controller (same identity) and written byte-exact, so it may be binary; it is not templated.
